# 全栈商城「前后端功能全部接真接口」实施计划

## 一、Summary（目标与范围）

把项目从「后端闭环已完成 + 前端大面积 mock」推进到 **前后端全部接真实接口、Docker Compose 一键起、开箱可用**。

**已确认的三条边界（用户已选定）**
1. **范围**：闭环 + 全部接真接口。补齐跑通闭环所必需的缺失页面与后端接口；**不新增**评价 / 收藏 / 独立搜索域 / 秒杀 / 品牌 等全新业务域。
2. **商家端入口**：复用 `admin-web`，按登录角色（平台 `admin` / 商家 `shop`）动态渲染菜单与路由。
3. **种子数据**：新增 Flyway 迁移补齐真实种子数据（分类 / 店铺 / SPU / SKU / 图片 / 库存 / 优惠券 / 会员），保证开箱即可看到完整效果。

### 前端 admin-web（Vue3 + Element Plus + Pinia）
- 路由/菜单**硬编码 5 项**（Dashboard / 类目 / SPU / 订单 / 商家审核），`Layout.vue` 菜单与 `pageTitle` 也是硬编码。
- `src/api/` 已有 `category.js / merchant.js / order.js / product.js / user.js`，但**页面基本未调用**：`Dashboard`（本地常量）、`Category`（本地 mock 树）、`ProductSpu`（本地 mock 列表 + 本地类目树）、`OrderManage`（本地 mock 订单）全为假数据；**仅 `MerchantAudit.vue` 与 `Login.vue` 为真接口**。
- `stores/user.js` 登录时把角色**写死为 `role:'admin'`**，未使用后端返回的 `userType`，故无法区分商家。
- `utils/request.js` 已注入 `admin_token`，401 清 token 跳登录。

### 前端 mobile-h5（Vue3 + Vant4）
- 已接真接口：`Cart.vue`、`OrderList.vue`、`OrderConfirm.vue`、`Payment.vue`、`Coupon.vue`、`Login.vue`、`OrderDetail.vue`；`ProductDetail.vue` 调 `getProductDetail/addToCart` 但**失败回退 mock**。
- **仍为纯 mock**：`Home.vue`（banners / 金刚区 / 秒杀 / 推荐 全部本地常量）。
- **缺失页面**：个人中心、收货地址管理、退款申请与列表、商品列表/分类页。
- `App.vue` TabBar 仅 3 项（首页/购物车/订单），**无「我的」**。
- `src/api/` 已有 `address.js / cart.js / coupon.js / order.js / pay.js / product.js / auth.js`。

### 数据/部署
- Flyway：`V1__init`（建表）、`V2__shop_apply`、`V3__seed_data`（**仅 2 个 sys_user：admin、shop，且 shop 无 shop_id**）、`V3_2`（修 shop 密码为 shop123）、`V4__seed_self_shop`（店铺 id=1）、`V5__refund`、`V6__coupon`。
- **无任何分类/SPU/SKU/库存/优惠券/会员种子数据** → 首页/详情/领券开箱即为空。
- **关键缺陷**：种子商家账号 `shop` 的 `shop_id` 为 NULL，`PermissionAspect` 会直接 403，商家端全部不可用。
- `docker-compose.yml` 已含 mysql/redis/minio/backend/admin-web/mobile-h5（前端挂载各自 `dist`），nginx 反代 `/api` → backend:8080。

## 三、Proposed Changes（具体改动）

### A. 后端

**A1. 新增迁移 `backend/src/main/resources/db/migration/V7__seed_catalog.sql`**（幂等，固定主键 + `ON DUPLICATE KEY UPDATE`）
- `UPDATE sys_user SET shop_id=1 WHERE username='shop'` —— 修复商家端 403（必须项）。
- `pms_category`：6 个一级（手机数码/电脑办公/家用电器/服饰鞋包/食品生鲜/美妆个护）+ 每类 2~3 个二级。
- `pms_spu`：8~12 条真实商品（`shop_id=1`，`status=1`，`audit_status=1`，`category_id` 指向二级，`main_image` 用占位图 URL，`min_price/max_price`）。
- `pms_sku`：每 SPU 1~2 个（`uk_sku_code` 唯一），写入 `pms_sku.stock`。
- `pms_spu_image`：每 SPU 若干轮播图。
- `wms_stock`：**每个 SKU 一行**（列名以 `V1__init.sql:441` 为准，含 `sku_id/spu_id/shop_id/available_stock/frozen_stock/...`），否则下单 `available_stock>=?` 无记录即失败。
- `pms_coupon`：2~3 张（1 张平台通用 `shop_id=NULL`，1~2 张店铺券 `shop_id=1`），`status=1`、`remain_count>0`。
- `user_member`：1 个测试会员（如手机号 `13800000000`），便于 C 端登录演示。

**A2. 平台统计接口** `backend/.../system/controller/AdminStatsController.java`
- `GET /api/admin/stats/overview`，`@RequirePermission("admin:stats:view")`
- 返回：会员总数、店铺数、订单总数、今日订单数、累计销售额（已支付）、待审核入驻数、待发货订单数、待处理退款数。
- 由新的 `AdminStatsService` 用 `selectCount` / `SUM` 聚合（不引第三方）。

**A3. 平台会员管理** `backend/.../system/controller/AdminMemberController.java`
- `GET /api/admin/members`（`PageQuery` + 可选 `keyword` 模糊 phone/nickname）→ `PageResult<MemberVO>`，权限 `admin:member:list`
- `POST /api/admin/members/{id}/status`（body `{status}` 0/1），权限 `admin:member:status`
- 复用现有 `MemberService` / `MemberVO`。

**A4. 商家端店铺信息** `backend/.../system/controller/ShopInfoController.java`
- `GET /api/shop/info` → `ShopVO`（本店），权限 `shop:info:view`
- `PUT /api/shop/info`（`contactName/contactPhone/province/city/district/address/description`），权限 `shop:info:update`
- `shopId` 一律取自 `@CurrentUser LoginUser.shopId()`，禁止前端传。

**A5. 商家端统计** `GET /api/shop/stats/overview`（本店商品数/订单数/待发货数/销售额），权限 `shop:stats:view`，复用 `AdminStatsService` 增加 `shopId` 维度重载。

**A6. 商家端优惠券** `backend/.../marketing/controller/ShopCouponController.java`
- 先核对 `CouponService.create(...)` 现有签名：若平台版写死 `shopId=null`，**保留原方法不动**，新增带 `shopId` 的重载。
- `GET /api/shop/coupons`、`POST /api/shop/coupons`、`POST /api/shop/coupons/{id}/status`；权限 `shop:coupon:list|create|status`；写入 `shop_id` = 当前店；查询/改状态时校验券归属（`coupon.shopId == 当前 shopId`）。

**A7. 错误码**：按需在 `ErrorCode.Biz` 追加（如 `MEMBER_NOT_FOUND`、`SHOP_NOT_FOUND`、`COUPON_FORBIDDEN`），沿用现有分段（30033 之后）。

**A8. 单测**（AGENTS.md 要求改逻辑补测）：`AdminStatsServiceTest`、`AdminMemberControllerTest`、`ShopInfoServiceTest`、`ShopCouponServiceTest`（重点：资源归属校验、平台/商家枚举维度正确）。
> 注：MyBatis-Plus 纯 Mockito 单测注意 TableInfo 预注册（见历史经验）。

## 四、Assumptions & Decisions

1. **短信验证码**：`MockSmsSender` 已开启，`/api/auth/sms/send` 返回 `devCode`，移动端登录页可展示/自动填充 → 演示无需真实短信通道。
2. **商家种子账号**：`shop / shop123`，V7 补 `shop_id=1`（否则 `PermissionAspect` 403）。测试商家需从 `admin-web` 登录（`/api/admin/login`）。
3. **平台券 vs 店铺券**：平台券 `shop_id=NULL`；店铺券 `shop_id=当前店`。`AdminCouponController` 逻辑**不改**，商家端另起 Controller + Service 重载。
4. **不新增业务域**：秒杀（表存在但不建控制器/页面）、品牌、评价、收藏、独立搜索引擎，均**不做**；Home 的「秒杀」位以「热销榜」替代。
5. **banners 静态**：无 CMS，保留前端本地运营图；其余首页数据全部接口化。
6. **平台订单/退款只读**：平台端仅查看，发货/退款审核在商家端（与现有后端职责一致）。
7. **图片**：种子数据用占位图 URL；上传走 `/api/files/upload`（MinIO 已就绪）。
8. 环境：Windows PowerShell 5；编译前设 `$env:JAVA_HOME="D:\app\jdk-21.0.12.1"`；Maven 用 `-o` 离线。
